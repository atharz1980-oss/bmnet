# مذكرة قرار — bucket صور المجتمع

> الحالة: **ينتظر قرار المالك.** لم يُنفَّذ أي خيار.
> تاريخ القياس: 2026-09-12. كل رقم هنا مُقاس على مشروع الإنتاج لا مفترض.

## المشكلة

`community-media` معرَّف `public: true`. نقطة `/object/public/` تخدم أي ملف فيه بصرف النظر عن سياسات `storage.objects`، فسياسات الرفع والتعديل والحذف تحكم الكتابة وحدها ولا تحكم القراءة.

أثران مؤكدان حيًا:

1. **إخفاء المنشور إشرافيًا لا يخفي صورته.** بعد الإخفاء ظل الرابط العام يعيد `200`.
2. **الحذف ليس فوريًا.** بعد حذف الكائن فعليًا: الرابط نفسه يعيد `200` مع `cf-cache-status: HIT`، والرابط مع كاسر تخزين يعيد `400`. أي أن CDN يخدم النسخة حتى ساعة (`cache-control: public, max-age=3600`).

## التوصية

**الخيار B، ويُنفَّذ قبل إطلاق المجتمع لا قبل الدمج.**

السبب: الفجوة ليست تسريب بيانات خاصة — الصور منشورة بإرادة أصحابها. الفجوة أنك **لا تستطيع إنزال صورة مخالفة فعليًا**، وهذه قدرة إشرافية أساسية لمنصة تستقبل محتوى مستخدمين. ومع صفر كائنات وصفر أعضاء، الكلفة اليوم هي تغيير كود فقط؛ بعد الإطلاق تصير ترحيل وسائط وكسر روابط محفوظة.

الثمن صريح ولا أخفيه: **فقدان تخزين CDN لصور المجتمع بالكامل.** لمجتمع تصوير الصور هي المنتج، وهذا يرفع زمن التحميل وحمل الأصل. يمكن تخفيفه لاحقًا بمدة توقيع أطول وتخزين على مستوى التطبيق، لكنه لن يعادل CDN.

**متى يصح الخيار A:** إن قررت أن المجتمع معرض أعمال لا منصة إشراف، وأن سحب صورة مخالفة يكفي فيه حذفها مع قبول تأخر ساعة. قرار تجاري مشروع، لكن سجّله صراحة حتى لا يُكتشف لاحقًا كعيب.

## إن اخترت B — نطاق العمل

1. `update storage.buckets set public = false where id = 'community-media'` وسياسة قراءة مقيدة.
2. `resolveCommunityMediaUrl` → توقيع على الخادم، وتوقيع دفعة واحدة في `loadCommunityFeed` و`loadPublicProfile` و`loadSavedPosts` تفاديًا لطلب لكل صورة.
3. `profile-editor` و`portfolio-manager` يستقبلان الروابط من الخادم بدل بنائها.
4. مدة التوقيع ومسلك انتهاء الصلاحية أثناء فتح الصفحة.
5. اختبار حي: صورة منشور مخفي غير قابلة للجلب، وصورة محذوفة تعيد 4xx فورًا.

لا شيء من هذا يمس `main` ولا يدخل PR #1.
