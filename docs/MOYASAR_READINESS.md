# جاهزية تفعيل ميسر — بيت المصور

تاريخ المراجعة: 2026-09-12. الموقع: https://baytalmosawer.net.

## الحالة

الموقع منشور على Hostinger، لكن الدفع الإلكتروني **غير جاهز للتحصيل بعد**. صفحة إعدادات الدفع الحالية تحفظ اسم المزود والتفعيل والبيئة فقط. لا يوجد Checkout أو جدول طلبات وتسجيلات أو تأكيد دفع أو Webhook. إدخال مفاتيح وحده في الحالة الحالية لا يكفي لتفعيل الدفع.

متطلبات ميسر الرسمية لمراجعة الموقع تشمل توضيح الخدمات والأسعار وسياسة الاسترجاع وقنوات التواصل. متطلبات حساب التاجر تشمل سجلًا تجاريًا سعوديًا أو وثيقة عمل حر صالحة وحسابًا بنكيًا تجاريًا مرتبطًا بها. مراجعة الموقع لا تعني ضمان قبول الحساب؛ القرار لدى ميسر.

المصدر: [أسئلة ميسر الشائعة](https://moyasar.com/en/resources/faqs/).

## نتيجة فحص الموقع المنشور

| البند | النتيجة | المطلوب |
|---|---|---|
| النطاق وHTTPS | يعملان | الحفاظ على شهادة SSL |
| وصف الدورات والأسعار | موجودان | اعتماد الأسعار والمواعيد ومعالجة الضريبة من المالك |
| الاتصال | رقم تجريبي +966551234567 ظاهر | رقم فعلي، بريد فعلي، عنوان وأوقات عمل معتمدة |
| هوية الجهة | الاسم التجاري ظاهر | الاسم القانوني وبيانات الترخيص التي يعتمدها المالك للنشر |
| سياسة الاسترجاع | منشورة | اعتمادها وإزالة الغموض بين 48 و72 ساعة قبل الدورة |
| مدة إعادة المبلغ | النص يذكر 5–10 أيام عمل | مراجعة الصياغة مع دورة معالجة المركز والبنك، دون وعد غير معتمد |
| الخصوصية | نص مختصر منشور | تحديثه لبيانات التسجيل ومزودي معالجة الدفع والتخزين ووسائل طلب الحقوق |
| الشروط والتسجيل والإلغاء | الصفحات متاحة | مطابقة النص مع طريقة الحجز والتنفيذ الفعلية |

| إعدادات ميسر | تفعيل/بيئة فقط | اختيار تخزين المفاتيح وتنفيذ الإدارة والتحقق من الاتصال |
| Apple Pay | غير متكامل | تهيئة واعتماد النطاق لدى ميسر عند طلبه؛ المفاتيح وحدها لا تكفي |

لا تُنشر بيانات قانونية أو هاتف أو بريد مفترض. لا يُختار معدل ضريبة أو مبلغ عربون أو سياسة إلغاء دون اعتماد المالك.

## قرارات تنتظر المالك

1. الاسم القانوني ورقم السجل/الترخيص الذي يريد نشره ووسائل التواصل الحقيقية.
2. اعتماد الدورات والأسعار والمواعيد والسياسات، وهل الأسعار شاملة الضريبة.
3. حفظ المفاتيح داخل لوحة الموقع بشكل مشفر، أم داخل متغيرات Hostinger مع إدارة التفعيل من الموقع.
4. سداد كامل سعر الموعد أم عربون. خيار العربون يحتاج قيمته وسياسة سداد الباقي.
5. أي قائمة متطلبات خاصة أرسلها فريق ميسر. لا حاجة لإرسال المفاتيح أو المستندات البنكية في المحادثة.

## متطلبات التكامل التقني

- المفتاح العام فقط يصل إلى نموذج الدفع. بيانات البطاقة تُرسل مباشرة إلى ميسر ولا تمر عبر خادم الموقع.
- المفتاح السري يبقى على الخادم ولا يُسلسل إلى AdminData أو PublicCmsProvider ولا يظهر في السجلات.
- إذا اختير الحفظ داخل الإدارة: فصل الأسرار عن payment_settings العامة للإدارة، تشفير موثق على الخادم بمفتاح مستقل في Hostinger، وحقول إدخال لا تعيد قراءة السر المحفوظ إلى المتصفح. التغيير والحذف للمالك وحده.
- إنشاء طلب مسجل في القاعدة قبل بدء الدفع، بسعر الموعد وعملته المحسوبين على الخادم. لا يعتمد التحصيل على السعر القادم من المتصفح.
- فصل test عن production وعدم اعتبار دفعة الاختبار حجزًا مدفوعًا حقيقيًا.
- التحقق من الدفع باسترجاعه من API ميسر بالمفتاح السري، ومطابقة المعرّف والحالة والمبلغ والعملة ومعرّف الطلب والبيئة. لا يكفي نجاح صفحة العودة أو بيانات المتصفح.
- تأكيد الحجز وزيادة المقاعد في معاملة واحدة تقاوم التكرار والتزامن؛ تحديد التعامل مع الدفع المتأخر والمقاعد الممتلئة دون ادعاء حجز مؤكد.
- Webhook موثّق وفق آلية ميسر الحالية، والتحقق من الدفع مرة أخرى، وتكرار المعالجة آمن. لا تخزين لبيانات البطاقة أو أجسام استجابات الدفع الكاملة.
- إظهار نجاح وفشل وتعليق التحقق بصدق، وإتاحة مرجع الطلب والدعم دون تسريب بيانات عميل آخر.
- إبقاء التحصيل مغلقًا حتى اكتمال البنية وتهيئة المفاتيح واختبار Sandbox. لا تُنفذ دفعة حقيقية ضمن الاختبارات دون إذن صريح.

العقد الحالي لا يحتوي جداول التسجيل والطلبات. أي إضافة لازمة للدفع تُجهّز كإضافة مستقلة وتُختبر في قاعدة محلية؛ لا إعادة migrations الحالية أو reset/drop/truncate/repair على Production.

## العمل الأولي في هذه المراجعة

أضيفت طبقة تحقق أولية للمبلغ والمفاتيح وهوية الدفع وربطه بالطلب، مع اختبارات لاستبدال المعرّف والمبلغ والعملة والبيئة وفشل المزود وتسريب الأخطاء. هذه طبقة داخلية أولية؛ لم تُربط بعملية Checkout ولم يُفعّل التحصيل. لا مفاتيح ميسر حقيقية متاحة لاختبار الشبكة؛ اختبارات API الحالية محاكاة HTTP.
